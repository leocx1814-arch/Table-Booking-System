# โครงสร้างหน้าเว็บแอปพลิเคชันฝั่งผู้ใช้งาน (Frontend Page & Navigation Structure)

เอกสารฉบับนี้จัดทำขึ้นโดย Senior Frontend Architect, UX/UI Designer และ Product Manager เพื่อกำหนดโครงสร้างหน้าจออินเตอร์เฟส (Frontend Page Structure) สำหรับ **ระบบจองโต๊ะโรงอาหารในสถานศึกษา (Canteen Table Booking System)** 

หน้าเว็บฝั่งผู้ใช้งานพัฒนาขึ้นภายใต้เทคโนโลยี **React 18 + Vite 5** ร่วมกับเครื่องมือคอมโพเนนต์ **MUI 5 (Material-UI)** และจัดการเส้นทางการเข้าหน้าจอด้วย **React Router** โดยอ้างอิงข้อมูลสัญญาระบบหลังบ้านใน [06-api-contract.md](file:///d:/Table-Booking-System/docs/planning/06-api-contract.md) และระบบสิทธิ์ใน [03-roles-permissions.md](file:///d:/Table-Booking-System/docs/planning/03-roles-permissions.md)

---

## 1. โครงสร้างเค้าโครงหน้าหลัก (Layout & Shell Systems)

ระบบเว็บแอปพลิเคชันจัดแบ่งเค้าโครงหน้าหลัก (Layout Types) ออกเป็น 3 รูปแบบตามกลุ่มผู้ใช้งานและความเหมาะสมของหน้าจออุปกรณ์:

### 1.1 เค้าโครงหน้าจอปกติ (User App Shell - Mobile-First Layout)
* **การใช้งาน:** นักศึกษา, บุคลากร, แม่บ้านทำความสะอาดประจำจุด
* **แถบนำทางส่วนบน (Topbar):** แสดงชื่อแอปพลิเคชัน โลโก้สถานศึกษา วิดเจ็ตนับถอยหลังการจอง/ใช้งานโต๊ะปัจจุบัน (Booking countdown card) และปุ่มกระดิ่งแจ้งเตือนเตือน
* **แถบนำทางส่วนล่าง (Bottom Navigation Bar):** ออกแบบให้สอดคล้องกับพฤติกรรมการใช้นิ้วโป้งกดมือถือขณะเดินในโรงอาหาร ประกอบด้วย 4 แท็บบันทึก:
  1. หน้าแผนผังที่นั่ง (`/` - Seat Map)
  2. ฟอร์มแจ้งเรื่องร้องเรียน (`/complaints/new` - File Report)
  3. หน้าประวัติธุรกรรม (`/history` - My Logs)
  4. ข้อมูลโปรไฟล์ส่วนตัว (`/profile` - Profile)

### 1.2 เค้าโครงหน้าจอด้านผู้ดูแลระบบ (Admin Console Layout)
* **การใช้งาน:** ผู้ดูแลระบบ, ผู้ตรวจการโรงอาหาร, ผู้บริหาร
* **แถบนำทางส่วนบน (Topbar):** ข้อมูลผู้ใช้ล็อกอิน เวลาเซิร์ฟเวอร์ และปุ่มออกจากระบบ
* **แถบนำทางส่วนข้าง (Sidebar Navigation):** เมนูสำหรับกดขยายเพื่อเลือกเข้าหน้าการจัดการข้อมูล การมอนิเตอร์ แผนผังโต๊ะ และระบบตั้งค่านโยบายทางธุรกิจ

## 2. รายละเอียดหน้าจอแยกตามกลุ่มผู้ใช้งาน (Frontend Page Specifications)

### 2.1 กลุ่มผู้ใช้ทั่วไป (นักศึกษา / บุคลากร)

#### A. หน้าหลักแผนผังที่นั่งแบบเรียลไทม์ (Live Interactive Seat Map)
* **URL Path:** `/`
* **ข้อมูลที่แสดง:**
  * แผนผังโรงอาหารจำลองแบบ Grid หรือ SVG โต๊ะแสดงสีตามสถานะ: **เขียว** (ว่าง), **เหลือง** (รอเช็คอิน), **แดง** (มีคนนั่งใช้งาน), **เทา** (งดใช้/ซ่อม)
  * วิดเจ็ตนับถอยหลังการจองโต๊ะปัจจุบัน ( countdown timer):
    * กรณีกดจองแล้ว: นับถอยหลัง 10 นาทีเพื่อเข้าเช็คอิน
    * กรณีเช็คอินใช้งานอยู่: นับถอยหลัง 30-45 นาทีก่อนหมดสิทธิ์นั่ง
* **ปุ่มและ Action สำคัญ:**
  * คลิกโต๊ะว่าง -> แสดงหน้าจอยืนยันเพื่อ "จองโต๊ะล่วงหน้า"
  * ปุ่ม "สแกน QR Code เพื่อเช็คอิน" (เปิดกล้องมือถือ)
  * ปุ่ม "คืนโต๊ะอาหาร (Check-out)" (หากทำเสร็จภารกิจก่อนหมดเวลา)
* **ฟอร์ม/กล่องข้อความ:** กล่อง Modal ยืนยันพิกัดจองโต๊ะ
* **ความเชื่อมโยงกับ API:**
  * `GET /api/v1/dashboard/canteen-status` (ซิงก์เรียลไทม์ผ่าน SSE)
  * `GET /api/v1/users/bookings/active`
  * `POST /api/v1/users/bookings`
  * `POST /api/v1/users/bookings/:id/check-in`
  * `POST /api/v1/users/bookings/:id/check-out`

#### B. หน้าฟอร์มส่งข้อร้องเรียน (Submit Complaint Form)
* **URL Path:** `/complaints/new`
* **ข้อมูลที่แสดง:**
  * รายละเอียดฟอร์มระบุคำขอความช่วยเหลือร้องเรียน
* **ปุ่มและ Action สำคัญ:**
  * ปุ่มสแกน QR Code ประจำโต๊ะที่เกิดปัญหา (เพื่อกรอกเลขโต๊ะอัตโนมัติ)
  * ปุ่มกดเปิดกล้องเพื่ออัปโหลด/ถ่ายภาพหลักฐาน (ขนาดไม่เกิน 5MB)
  * ปุ่มกดเลือกว่า "ไม่ประสงค์ออกนาม (Anonymous)"
  * ปุ่ม "ส่งข้อร้องเรียน"
* **ฟอร์ม/กล่องข้อความ:** ฟอร์มรับข้อมูลเรื่องร้องเรียน (ประกอบด้วย: หมายเลขโต๊ะ, ประเภทปัญหา, รายละเอียดข้อความ, ภาพหลักฐาน)
* **ความเชื่อมโยงกับ API:**
  * `GET /api/v1/complaint-categories`
  * `POST /api/v1/attachments/upload`
  * `POST /api/v1/complaints`

#### C. หน้าประวัติและสถานะร้องเรียน (My History & Log Status)
* **URL Path:** `/history`
* **ข้อมูลที่แสดง:**
  * ตารางประวัติการจองย้อนหลัง (วันเวลา, หมายเลขโต๊ะ, ระยะเวลานั่ง, สถานะการจอง)
  * รายการข้อร้องเรียนที่เคยส่งเข้าไป พร้อมระบุสถานะสีตามความก้าวหน้า (`รอยืนยัน`, `กำลังตรวจสอบ`, `เสร็จสิ้น`) และข้อบันทึกชี้แจงของแอดมิน
  * ตารางบันทึกการโดนตัดคะแนนประพฤติ (ถ้ามี)
* **ปุ่มและ Action สำคัญ:**
  * คลิกเรื่องร้องเรียน -> แสดง Modal รายละเอียดเหตุผลและการเคลียร์
* **ความเชื่อมโยงกับ API:**
  * `GET /api/v1/users/profile`

#### D. หน้าประวัติส่วนตัวและคะแนนประพฤติ (Profile & Account Status)
* **URL Path:** `/profile`
* **ข้อมูลที่แสดง:**
  * ข้อมูลรหัสนักศึกษา, ชื่อ-นามสกุล, อีเมล, สังกัดคณะ
  * แผงแสดงคะแนนความประพฤติ (Penalty Points) (คะแนนเต็ม 100 หากต่ำกว่า 50 จะขึ้นแถบสีแดงระบุสถานะ Blacklisted)
* **ปุ่มและ Action สำคัญ:**
  * ปุ่ม "เปลี่ยนรหัสผ่าน (Change Password)"
  * ปุ่ม "ลงชื่อออกจากระบบ (Logout)"
* **ความเชื่อมโยงกับ API:**
  * `GET /api/v1/users/profile`
  * `POST /api/v1/auth/logout`

### 2.2 กลุ่มเจ้าหน้าที่ทำความสะอาด (Canteen Cleaners)

#### A. หน้ากระดานงานทำความสะอาดโต๊ะ (Cleaners Task Board)
* **URL Path:** `/cleaner/dashboard`
* **ข้อมูลที่แสดง:**
  * แผงการ์ดรายการโต๊ะแยกตามโซนรับผิดชอบ
  * รายการโต๊ะที่ติดสถานะ `need_cleaning` (เพิ่งใช้งานเช็คเอาต์ หรือจองเลยเวลา)
* **ปุ่มและ Action สำคัญ:**
  * ปุ่มกดขนาดใหญ่สีส้ม "เริ่มทำความสะอาดโต๊ะ" (เปลี่ยนสถานะเป็น `cleaning`)
  * ปุ่มกดขนาดใหญ่สีเขียว "ทำความสะอาดเสร็จสิ้น" (เปลี่ยนสถานะเป็น `available`)
* **ความเชื่อมโยงกับ API:**
  * `GET /api/v1/dashboard/canteen-status` (คัดกรองเฉพาะสถานะความสะอาด)
  * `POST /api/v1/table-cleaning-logs`

### 2.3 กลุ่มผู้ตรวจการโรงอาหาร (Canteen Inspectors)

#### A. แผงควบคุมตรวจตราเรื่องร้องเรียนหน้างาน (Inspector Investigation Center)
* **URL Path:** `/inspector/dashboard`
* **ข้อมูลที่แสดง:**
  * คิวรายการเรื่องร้องเรียนเร่งด่วนเรียงตามเวลาที่แจ้งเข้ามา
  * แผงแสดงพิกัดแผนผังโต๊ะที่มีเครื่องหมายตกใจระบุจุดที่มีข้อพิพาท/มีคนแจ้งร้องเรียนกั๊กที่นั่ง
* **ปุ่มและ Action สำคัญ:**
  * ปุ่ม "รับเรื่องตรวจสอบ (Investigate)" -> ล็อกเรื่องให้อยู่ในความรับผิดชอบ
  * ปุ่ม "ยืนยันการทำผิดกฎ (Verify Violation)" -> ทำการตัดสินหักคะแนนเป้าหมาย 20 คะแนน ปล่อยโต๊ะคืน และปิดเคส
  * ปุ่ม "ยกเลิกคำร้องเรียน (Dismiss Complaint)" -> กรณีเรื่องไม่มีมูลความจริง หรือเป็นการแกล้งกัน
  * ปุ่ม "สั่งแมนนวลเช็คเอาต์ (Manual Checkout)" -> เพื่อล้างสถานะโต๊ะหน้างาน
* **ฟอร์ม/กล่องข้อความ:** กล่องรับรายละเอียดเขียนระบุเหตุผลตัดสิน (Inspector Remarks)
* **ความเชื่อมโยงกับ API:**
  * `GET /api/v1/complaints`
  * `POST /api/v1/complaints/:id/assign`
  * `PATCH /api/v1/complaints/:id/status`

### 2.4 กลุ่มผู้ดูแลระบบ (System Administrators)

#### A. แผงควบคุมสรุปข้อมูลส่วนกลาง (Super-Admin Dashboard)
* **URL Path:** `/admin/dashboard`
* **ข้อมูลที่แสดง:**
  * Dashboard Cards สรุปสถิติสด: Live Occupancy Rate, ยอดคำร้องเรียนค้างสะสม, ยอดผู้จองวันนี้, บัญชีผู้โดนแบนสะสม
  * แผนผังประเมินทราฟฟิกแยกช่วงเวลาโรงอาหาร
* **ความเชื่อมโยงกับ API:**
  * `GET /api/v1/dashboard/canteen-status`
  * `GET /api/v1/dashboard/complaints-summary`

#### B. หน้าประมวลผลและจัดการข้อร้องเรียนส่วนกลาง (Central Complaint Management)
* **URL Path:** `/admin/complaints`
* **ข้อมูลที่แสดง:**
  * Datagrid รายการเรื่องร้องเรียนจากทุกช่องทาง (Web App, โทรศัพท์, API ส่วนกลาง)
* **ปุ่มและ Action สำคัญ:**
  * ปุ่ม "ลงบันทึกร้องเรียนทางโทรศัพท์ (Phone-in Log)" -> เปิดแบบฟอร์มคีย์ข้อมูล
  * ปุ่ม "นำเข้าข้อมูลจากระบบกลาง (Central Import)" -> อัปโหลดไฟล์ CSV/Excel
* **ฟอร์ม/กล่องข้อความ:**
  * แบบฟอร์มบันทึกการร้องเรียนทางโทรศัพท์ (ประกอบด้วย: ผู้โทรแจ้ง, เบอร์โทรศัพท์ติดต่อ, เลขโต๊ะ, รายละเอียดปัญหา)
* **ความเชื่อมโยงกับ API:**
  * `GET /api/v1/complaints`
  * `POST /api/v1/complaints/phone-log`
  * `POST /api/v1/complaints/import-central`

#### C. หน้าการบริหารข้อมูลผังที่นั่งโรงอาหาร (Table & Layout Configuration)
* **URL Path:** `/admin/tables`
* **ข้อมูลที่แสดง:**
  * ตารางรายการข้อมูลโต๊ะ โซน และพิกัดตำแหน่งแสดงผล
* **ปุ่มและ Action สำคัญ:**
  * ปุ่ม "เพิ่มโต๊ะอาหารใหม่ (Add Table)" หรือ "ลบโต๊ะ"
  * ปุ่ม "ดาวน์โหลดแผ่น QR Code ประจำโต๊ะ"
* **ฟอร์ม/กล่องข้อความ:** ฟอร์มป้อนข้อมูลเพิ่ม/แก้ไขพิกัดและหมายเลขโต๊ะ
* **ความเชื่อมโยงกับ API:** Table CRUD REST APIs และ QR Code Service

#### D. หน้าควบคุมรายชื่อและการลงโทษทางวินัย (User & Blacklist Center)
* **URL Path:** `/admin/users`
* **ข้อมูลที่แสดง:**
  * ตารางรายชื่อนักเรียนที่มีคะแนนประพฤติต่ำกว่าเกณฑ์ และผู้ใช้งานที่กำลังโดนแบนในตาราง Blacklist
* **ปุ่มและ Action สำคัญ:**
  * ค้นหารหัสนักศึกษา
  * ปุ่ม "กู้คืนแต้มประพฤติ / ปลดแบนแมนนวล (Manual Unban Override)"
* **ฟอร์ม/กล่องข้อความ:** ฟอร์มกรอกเหตุผลชี้แจงในการปลดแบนแมนนวล (Audit Required)
* **ความเชื่อมโยงกับ API:** Unban และ Blacklist override APIs

#### E. หน้ากำหนดเกณฑ์และกฎทางธุรกิจ (Business Rules Settings)
* **URL Path:** `/admin/settings`
* **ข้อมูลที่แสดง:**
  * แผงแก้ไขค่าคงที่ทางธุรกิจของระบบจอง
* **ปุ่มและ Action สำคัญ:**
  * ปุ่ม "บันทึกการเปลี่ยนแปลงนโยบาย"
* **ฟอร์ม/กล่องข้อความ:** ฟอร์มกรอกค่าตั้งค่า (เวลานั่งจองสูงสุด, รอยะเวลา Grace Period, พิกัดตำแหน่งศูนย์กลางโรงอาหาร GPS, รัศมีขอบเขต GPS)
* **ความเชื่อมโยงกับ API:** System settings GET/PATCH APIs

### 2.5 กลุ่มผู้บริหาร (School Executives)

#### A. หน้ารายงานสถิติและวิเคราะห์ข้อมูลเชิงลึก (Analytical Executive Reports)
* **URL Path:** `/executive/reports`
* **ข้อมูลที่แสดง:**
  * แผงแผนภาพสถิติ (Line/Bar Charts) แสดงอัตราความหนาแน่นเฉลี่ยรายคาบ
  * สรุปอัตราส่วนประเภทเรื่องร้องเรียนที่เกิดในโรงอาหารรายเดือน
  * ตารางสรุปการหักคะแนนความประพฤติสะสมและสถิติคนทำผิดกฎบ่อย
* **ปุ่มและ Action สำคัญ:**
  * ปุ่ม "ส่งออกรายงานเป็นไฟล์ PDF / พิมพ์เอกสาร"
* **ความเชื่อมโยงกับ API:**
  * `GET /api/v1/reports/violations`
  * `GET /api/v1/reports/canteen-usage`
